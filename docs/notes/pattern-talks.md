# Pattern шийдвэрийн хүснэгт (Week 5, Structural patterns)

| Дэд систем | Сонгосон pattern | Яагаад сонгосон | Сонгоогүй pattern ба шалтгаан |
|---|---|---|---|
| Хэрэглэгчийн интеграци | Adapter | Гадны хуучин системийн `ExternalCustomer` өгөгдлийг манай `Customer` болгон хөрвүүлж, хуучин системийн бүтцийг домэйнээс тусгаарлана. | Decorator-ыг сонгоогүй: энд зорилго нь API-г хөрвүүлэх, харин хэрэглэгчийн ажиллагааг нэмэгдүүлэх биш. |
| Худалдан авалтын урсгал | Facade | Нөөц, төлбөр, захиалгыг зохицуулах нэг орох цэг өгч, контроллерыг гурван сервисээс салгана. | Mediator-ыг сонгоогүй: дэд системүүд хоорондоо харилцах биш, нэг чиглэлд дарааллаар дуудагдана. |
| Бүтээгдэхүүний репозитори | Decorator | Интерфэйс болон өгөгдлийн сангийн кодыг өөрчлөхгүйгээр дуудалтыг тоолж хэмжинэ. | Proxy-г сонгоогүй: wrapper нь хандалтыг хянахгүй, зөвхөн хэмжилт нэмдэг. |
| Захиалгын мөрүүд | Composite | Нэг бараа болон багц барааг адилхан ашиглаж, нэхэмжлэхийн үнийг `instanceof`-гүйгээр модоор тооцно. | Chain of Responsibility-г сонгоогүй: мөрүүд нь дараалсан боловсруулагч биш, бүхэл-хэсэг модон бүтэцтэй. |
| Барааны каталог | Proxy | Давтан хайлтыг санах ойн кэшээс хариулж, удаан каталогийг хамгаална. | Adapter-ыг сонгоогүй: Proxy нь Catalogue-ийн интерфэйсийг хэвээр хадгалдаг, үл нийцэх API-г холбодоггүй. |
